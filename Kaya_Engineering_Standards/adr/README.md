## Numbering

Use sequential numbers:

`ADR-0001-short-title.md`

Never reuse a number.

## Status

Allowed status values:

- Proposed
- Accepted
- Superseded
- Deprecated
- Rejected

A superseded ADR should link to its replacement.

## When to create an ADR

Create an ADR for changes to major frameworks, authentication, authorisation, encryption, deployment topology, task ownership, shared module architecture or another decision expected to shape future work.

Do not create an ADR for routine implementation choices.
